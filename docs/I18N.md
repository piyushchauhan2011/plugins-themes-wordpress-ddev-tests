# Internationalization and localization

Hotel Booking splits language work the same way WordPress does.

**Layer A — software strings (shipped).** Theme chrome and plugin UI use gettext. **Source catalogs** are `.pot` and `.po` in each `languages/` folder. Spanish (`es_ES`) is a working example. Compiled `.mo`, `.l10n.php`, and plugin editor `.json` are generated (`ddev compile-i18n`) and gitignored.

**Layer B — editorial content and UGC (not wired).** Room titles, page copy, menus, and `hotel_name` are `wp_posts` / options. Inquiry rows are guest-generated. Neither belongs in a `.po` file. A multilingual plugin (Polylang/WPML) would add **linked copies** of posts later. Do **not** add translation columns to `wp_hb_inquiries`.

```
WPLANG / user locale
  ├─ Layer A  theme hotel-booking-*.mo + plugin hotel-booking-core-*.mo
  │            labels, errors, pattern chrome, status labels
  └─ Layer B  hb_room, pages, menus, hotel_name (later: language copies)
               wp_hb_inquiries rows stay in the guest’s own words
```

Switching the site to Spanish translates **Send inquiry** and **Pending**. Seeded room titles (**Deluxe King**) and guest messages stay English until Layer B exists.

## What we have today

| Piece | Layer | Where |
| --- | --- | --- |
| Theme UI | A | Text domain `hotel-booking`, [`load_theme_textdomain`](../wp-content/themes/hotel-booking/functions.php), [`languages/`](../wp-content/themes/hotel-booking/languages/) |
| Plugin UI | A | Text domain `hotel-booking-core`, [`load_plugin_textdomain`](../wp-content/plugins/hotel-booking-core/hotel-booking-core.php), [`languages/`](../wp-content/plugins/hotel-booking-core/languages/) |
| Inquiry status | A labels, B keys | Slugs `pending`, `contacted`, `closed` in MySQL; [`hotel_booking_inquiry_status_label()`](../wp-content/plugins/hotel-booking-core/inc/inquiries.php) for display |
| Rooms | B | `hb_room` posts: title, excerpt, content. Numeric meta is locale-neutral |
| Inquiries | B (do not translate) | [`wp_hb_inquiries`](../wp-content/plugins/hotel-booking-core/inc/database.php) guest fields |
| Seed | B English | [`ddev seed-content`](../content/README.md) |

## Layer A — gettext

Two domains, never mixed:

- Theme: `__( '…', 'hotel-booking' )`
- Plugin: `__( '…', 'hotel-booking-core' )`

HTML templates cannot call `__()`. User-facing chrome lives in PHP patterns (`patterns/404.php`, `footer-bar.php`, `rooms-archive.php`, …) that templates include with `<!-- wp:pattern -->`.

Interactivity JS must read strings from `wp_interactivity_state()` (see the color scheme toggle). Do not hardcode English in `view.js`.

Editor scripts in the plugin use `@wordpress/i18n`. `wp_set_script_translations()` plus `wp i18n make-json` Jed files in the plugin `languages/` folder load Spanish in the block editor.

### Regenerating catalogs

```bash
ddev make-pot
```

That overwrites **`.pot` only**. Merge into hand-translated `.po` with `wp i18n update-po`, then compile (gitignored) binaries:

```bash
ddev compile-i18n
```

### Try Spanish locally

The header **English / Español** links set a `hotel_booking_locale` cookie (`?lang=es_ES` then redirect). That overrides `WPLANG` on the front only; wp-admin stays on the site/user language. Room titles stay English (Layer B).

Default site language stays English so Playwright specs keep matching **Send inquiry** unless a test clicks Español.

You can still force the whole site with:

```bash
ddev wp language core install es_ES
ddev wp option update WPLANG es_ES
```

Core UI (wp-admin chrome, dates) comes from the WordPress.org language pack. Theme and plugin chrome come from the shipped `.mo` / `.l10n.php` files. The site title and seeded room names stay English (Layer B).

## Layer B — content and tables (not deployed)

| Content | Approach |
| --- | --- |
| `hb_room`, pages, menus | Polylang or WPML: one post per locale, linked. Not extra columns on `wp_posts`. |
| `hotel_name` setting | One brand string, or a translatable option later — not gettext. |
| Inquiry **rows** | Never duplicate. Name, email, message, dates are UGC. |
| Inquiry **status** | Keep English keys in SQL. Translate labels in Layer A. |
| `room_id` on an inquiry | Points at one post ID. Language-aware linking is the multilingual plugin’s job. |
| REST / search | Filter rooms in the current locale; `price_formatted` is already gettext (`$%s / night`). |

Optional later: store the **guest UI locale** on the row (which language the form was in), not a translation of the message. Sketch only: [`snippets/inquiries-locale-column.php.example`](snippets/inquiries-locale-column.php.example). That is **not** in `dbDelta`.

No Polylang/WPML in DDEV. No second seeded language for rooms.
